# 分類の扱い

詳細は `docs/01-information-architecture.md` と `docs/03-content-model.md`。

## 原則

分類は「階層」ではなく「属性」。テーマ×業界×職種×地域×形式の5軸を多対多で持つ。

1記事を1カテゴリに固定しない。同じコンテンツが複数の入口から発見できる状態を維持する。

## 禁止

- 未定義のIDをコンテンツ側で使う。追加は必ず `data/taxonomies/` のマスター更新を経由する
- 業界と職種を親子関係にする（「事務」は全業界に存在する）
- タグを自由入力にする
- 属性が存在することを理由に一覧ページを生成する。属性の保持と公開ページの存在は別
- 業界×テーマ、地域×業界などの組み合わせページを自動生成する

## ID命名

英小文字・kebab-case・英語。表示用の日本語ラベルはマスター側の `label` で持ち、IDと分離する。

## primaryTheme

全コンテンツに1つ設定し、`themes` にも含める。通常記事のURLはprimaryThemeから生成されるため、公開後は変更しない。
