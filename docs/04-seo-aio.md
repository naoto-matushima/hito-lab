# 人手不足研究所｜04 SEO・AIO設計書 v1.0
**文書名:** 04-seo-aio.md
**対象サイト:** 人手不足研究所
**位置づけ:** 00 基本設計書、01 情報設計書、02 サイトマップ・URL設計書、03 コンテンツモデル仕様書の下位設計書
**目的:** 人手不足研究所がGoogle検索およびAI検索において、特定テーマ・業界に関する信頼できる情報源として認識され、長期的に主要カテゴリで高い検索可視性を獲得するためのSEO・AIO方針を定義する。

# 1. SEO・AIOの基本戦略
人手不足研究所では、SEOを単純な「検索キーワードごとの記事量産」として捉えない。

サイト全体として、

**一次情報を積み上げ、テーマの代表的な情報源になる。**

ことを最上位方針とする。

Googleは、独自の情報・レポーティング・調査・分析や、他の検索結果と比較したときの付加価値を、コンテンツ品質を考えるうえで重要な観点として明示している。

そのため人手不足研究所では、以下を中心的なSEO資産とする。

- 企業インタビュー
- 働く人へのインタビュー
- 採用支援会社・人事支援会社・IT支援会社へのインタビュー
- 独自アンケート
- 公的統計の独自分析
- 複数統計を組み合わせた分析
- 業界比較
- 地域比較
- 職種比較
- 実際の改善事例
- 独自レポート

# 2. 長期的に目指す状態
人手不足研究所では、初期からロングテールキーワードだけを狙うことを最終目的としない。

最終的には、

採用

人材確保

人手不足

組織

人材定着

業務改善

DX

など、比較的大きな検索テーマにおいて、テーマカテゴリトップ自体が高く評価される状態を目指す。

ただし、ビッグキーワードを狙うためだけにカテゴリページを作るのではない。

以下の順序で専門性と信頼性を蓄積する。

一次情報を作る

↓

個別コンテンツとして公開する

↓

記事・レポート・インタビューを相互に関連付ける

↓

テーマ・業界単位で情報を集約する

↓

カテゴリトップ・業界ハブを継続的に強化する

↓

結果として大きな検索テーマでも評価される状態を目指す

# 3. SEO資産の4階層
人手不足研究所のSEOコンテンツは、以下の4階層で考える。

## 3-1. テーマハブ
例：

/recruiting/

/organization/

/dx/

/management/

長期的に主要キーワードを狙う最上位SEO資産。

## 3-2. 業界ハブ
例：

/industries/construction/

/industries/nursing-care/

/industries/logistics/

特定業界についての専門性を示す資産。

## 3-3. 個別検索コンテンツ
例：

建設業は本当に人手不足なのか

建設業の採用単価

介護職が辞める理由

物流業のDX

具体的な検索意図を取得する。

## 3-4. 一次情報コンテンツ
例：

独自レポート

企業インタビュー

求職者インタビュー

アンケート

事例

検索ボリュームの有無にかかわらず、サイト全体の独自性・信頼性を作る。

# 4. 各コンテンツのSEO上の役割
| **コンテンツ** | **主な役割** |
| --- | --- |
| テーマハブ | ビッグキーワード・情報集約 |
| 業界ハブ | 業界専門性・業界検索 |
| Article | 個別検索意図の獲得 |
| Report | 一次情報・引用・被リンク・リード獲得 |
| Interview | 一次情報・信頼性・関係構築 |
| Case | 課題解決・具体性・CV |
| About | ブランド・運営主体の信頼性 |

すべてのページに同じKPIを求めない。

# 5. テーマハブSEO
テーマトップは、単なる記事一覧ページにしない。

対象：

/recruiting/

/organization/

/dx/

/management/

テーマ全体を体系的に理解できる編集ページとする。

テーマごとに以下を持つ。

テーマの定義

↓

主要課題

↓

基礎データ

↓

主要な解決アプローチ

↓

業界別の違い

↓

独自レポート

↓

インタビュー

↓

重要記事

↓

最新記事

# 7. テーマハブの長期SEO目標
例として/recruiting/は、

採用

人材採用

人材確保

採用方法

採用戦略

等の比較的大きな検索テーマを長期的な対象候補とする。

ただし、検索ボリュームだけで狙うキーワードを決定せず、

- 人手不足研究所のブランドとの整合性
- 下位コンテンツの充実度
- 一次情報の蓄積
- 読者への価値
- 競合状況

を踏まえて決定する。

業界ページはタグ一覧ではなく、その業界における人手不足・採用・組織・DXを統合したページとする。

例：

/industries/construction/

例：建設

# 10. テーマ軸と業界軸の二方向構造
人手不足研究所は、

テーマ

×

業界

の二方向から専門性を形成する。

例えば「建設業の採用」に関する記事は、

/recruiting/

の専門性にも寄与し、

/industries/construction/

の専門性にも寄与する。

# 11. Article SEO
Articleは具体的な検索意図を取得する。

例：

建設業 人手不足

建設業 採用単価

施工管理 採用

介護 離職率

ホテル 予約システム

Excel 業務改善

# 12. Articleの検索意図
1ページにつき、主要な検索意図を原則1つ定義する。

同じページで複数の異なる検索意図を無理に狙わない。

ただし、関連するサブクエリについては一つの記事内で体系的に答える。

# 13. Articleとカテゴリトップの役割分担
例えば、

/recruiting/

は採用全体。

/recruiting/construction-recruitment-cost/

は建設業の採用単価。

のように粒度を分ける。

個別Articleでビッグキーワードの網羅を狙わない。

# 14. Report SEO
Reportは人手不足研究所の中核SEO/AIO資産とする。

主な目的：

- 独自情報の公開
- 被リンク獲得
- AI・メディア等からの引用
- ブランド認知
- レポートダウンロード
- 関連テーマのSEO強化

# 15. ReportページをフォームLPにしない
Reportページは、PDFダウンロードフォームだけではなく、Web上でも価値のある情報を十分に公開する。

基本構成：

調査概要

↓

結論・重要な発見

↓

主要データ

↓

グラフ・図表

↓

解説

↓

調査方法

↓

関連コンテンツ

↓

PDFダウンロード

↓

出典

# 16. Reportの検索意図
Reportでは、

○○業界 人手不足 レポート

○○業界 採用 調査

○○業界 人材 調査

等を対象候補とする。

ただしReportの最重要価値は、既存検索需要だけでなく、**人手不足研究所独自の引用可能な情報資産を作ること**に置く。

# 17. ReportとArticleのカニバリ防止
例えば、

/recruiting/construction-labor-shortage/

と、

/reports/construction-labor-shortage-2026/

が存在する場合、役割を明確に分ける。

### Article
「建設業はなぜ人手不足なのか」を体系的に解説。

### Report
特定年の調査結果、独自分析、アンケート、インタビュー等をまとめる。

両ページは相互リンクする。

# 18. Interview SEO
Interviewは検索ボリュームを主要KPIとしない。

主なSEO/AIO上の価値：

- 一次情報
- 独自性
- 実体験
- 企業事例
- 専門性
- Reportの根拠
- 被リンク機会
- 指名検索

# 19. Interviewタイトル
検索キーワードを不自然に詰め込まず、

○○建設に聞く、若手採用と定着の取り組み

のように、

**企業・人物 + 読者にとって価値のあるテーマ**

を明確にする。

# 20. 一次情報戦略
人手不足研究所では一次情報の蓄積を最重要編集方針とする。

優先度の高い一次情報：

### 企業側
- 経営者
- 人事
- 管理職
- 現場責任者

### 働く側
- 現場職
- 若手
- 転職者
- 経験者
- 未経験者

### 支援側
- 採用会社
- 人材会社
- 社労士
- 組織コンサル
- IT会社
- DX会社

# 21. アンケート・調査
独自アンケートでは、

- 調査対象
- 調査方法
- 調査期間
- 回答数
- 設問
- 回答結果
- 集計方法

を可能な限り公開する。

小規模調査については、回答数を誇張せず、その範囲で得られる示唆として扱う。

# 22. 公的統計の独自分析
単に公的統計を転載しない。

例えば、

建設投資額

+

就業者数

+

技能者数

+

年齢構成

を組み合わせ、

仕事量は増えている一方、働き手が減っている

など、人手不足研究所独自の問い・分析を加える。

# 23. AIO基本方針
Googleは、AI OverviewsやAI Modeへの掲載について特別なAI専用SEO要件はなく、従来のSEO基盤、クロール可能性、内部リンク、ページ体験、重要情報のテキスト化、構造化データと表示内容の一致などが引き続き重要としている。

したがって、人手不足研究所では「AIO専用テクニック」の導入を目的としない。

# 24. AIOで目指す状態
目標例：

人手不足研究所の調査によると……

人手不足研究所が○社に行ったインタビューでは……

人手不足研究所の2026年レポートでは……

のように、情報源として参照される状態。

# 25. AIに引用される価値のある情報
特に以下を重視する。

- 他サイトに存在しない調査結果
- 独自インタビュー
- 独自アンケート
- 複数統計の独自分析
- 明確な数字
- 企業事例
- 地域別データ
- 業界別比較
- 更新された最新情報

# 26. 引用単位の設計
重要情報を長文の中に埋め込むだけにしない。

推奨構造：

問い

↓

結論

↓

数値・事実

↓

出典

↓

解釈

例：

### 建設技能者は20年間で約92万人減少
本文……

**出典：○○**

という形で重要な事実を明確にする。

# 27. 要点ブロック
Reportや長文Articleでは、ページ冒頭付近に、

この記事・調査で分かること

または、

重要なポイント

を設置できるようにする。

ただし、本文を読まなくても済むほど内容を削りすぎない。

# 28. E-E-A-T・信頼性設計
Googleは、明確な出典、著者情報、サイト運営者情報など、ユーザーがコンテンツを信頼できる情報を提供することを推奨している。

03で定義した以下を積極的に利用する。

Authors

Editors

Reviewers

Sources

Companies

Research Method

PublishedAt

UpdatedAt

可能な範囲で以下を表示する。

- 執筆者
- 編集者
- 監修者
- 公開日
- 更新日
- 調査方法
- 調査対象
- 参考資料
- 出典

# 30. AboutページのSEO/AIO上の役割
/about/には最低限以下を掲載する。

- 人手不足研究所とは
- 運営目的
- 対象テーマ
- 対象業界
- 運営者
- 編集方針
- 調査方針
- 取材方針
- 問い合わせ方法

将来的に、

/editorial-policy/

/correction-policy/

等の独立も検討する。

# 31. 訂正方針
統計数値・企業情報等に誤りが判明した場合、速やかに訂正できる運用を作る。

重要な修正については更新履歴に記録する。

# 32. 内部リンク戦略
内部リンクは単なる関連記事表示ではなく、サイトの専門構造を形成するために利用する。

基本：

テーマハブ

↕

Report

↕

Article

↕

Interview / Case

双方向にリンクする。

# 33. 上位ハブへのリンク
Articleから原則として、

primaryTheme

のテーマトップへリンクする。

該当する業界ハブが公開済みの場合は業界ハブにもリンク可能とする。

# 34. Reportへのリンク
関連Reportが存在するArticleでは、優先的にReportへの導線を作る。

例：

建設業 人手不足記事

↓

建設業人手不足レポート

# 35. ReportからArticleへのリンク
Reportでは、主要な論点を詳しく解説するArticleへリンクする。

Reportを行き止まりにしない。

# 36. Interviewへのリンク
ArticleやReport内で企業事例・働く人の声を扱う場合、関連Interviewへリンクする。

# 37. 関連記事の自動生成
03の、

primaryTheme

industry

job

area

tag

を利用する。

ただし編集上重要なコンテンツはrelatedContentで手動指定し、自動関連記事より優先する。

# 38. タイトル設計
タイトルは検索キーワードだけでなく、ユーザーが内容を判断できる表現を優先する。

Googleもページタイトル・主見出しについて、内容を説明する分かりやすい表現を推奨している。

# 39. SEO title
03のoverrideがない場合、基本：

{title}｜人手不足研究所

とする。

ただし文字数等を理由に機械的にブランド名を必ず追加するのではなく、表示・可読性を考慮する。

# 40. H1
原則1ページ1H1とする。

H1はページ内容を最も自然に表す日本語とする。

# 41. 見出し設計
H2・H3は、

- ユーザーの疑問
- 結論
- 論点
- 比較軸

が分かる表現を優先する。

キーワードを入れること自体を目的にしない。

# 42. meta description
検索順位を直接上げることだけを目的とせず、

- 誰向けか
- 何が分かるか
- 独自性
- データ・調査の有無

を簡潔に説明する。

# 43. サイト名
サイト名は、

人手不足研究所

に統一する。

Googleはサイト名認識にホームページ上の表記やWebSite構造化データなどを利用しており、サイト名は一貫して使用することを推奨している。

# 44. Organization / WebSite
ホームページで、

WebSite

Organization

の情報を明確に定義する。

表示名：

人手不足研究所

ブランド表記をページごとに変更しない。

# 45. 構造化データ基本方針
構造化データは、検索順位操作を目的とせず、ページの意味を機械に伝えやすくするために利用する。

構造化データの内容はページ上でユーザーに表示されている内容と一致させる。GoogleもAI検索を含め、構造化データと可視コンテンツを一致させることを推奨している。

# 46. Article構造化データ
Articleで利用。

主な連携：

headline

description

image

author

datePublished

dateModified

publisher

# 47. Interview構造化データ
基本はArticle系を利用する。

人物については必要に応じてPersonを関連付ける。

Company Masterの企業についてはOrganization情報を利用可能とする。

# 48. Report構造化データ
Reportの内容に応じて、

Article

Dataset

等を使い分ける。

# 49. Dataset
独自データセットとして十分な内容を持つ場合、Dataset構造化データを検討する。

GoogleはDatasetについて、名前、説明、作成者、配布情報等のメタデータを提供することでデータセットの発見を支援するとしている。

すべてのレポートへ機械的にDatasetを付与しない。

# 50. Dataset適用候補
例：

- 独自アンケート集計
- 業界別人手不足データ
- 地域別採用データ
- CSV等で提供する独自データ
- 継続更新する時系列データ

# 51. BreadcrumbList
02のパンくず方針に沿って構造化する。

Googleは、URL階層をそのままコピーするのではなく、典型的なユーザー経路を表すパンくずを推奨している。

# 52. sitemap.xml
index対象ページのみを基本的に掲載する。

対象：

- TOP
- テーマハブ
- Article
- Report
- Interview
- 公開済み業界ハブ
- About等

# 53. noindexページ
02の方針に従う。

例：

- 検索結果
- フィルタ結果
- 薄いタグページ
- 管理用ページ
- 重複ページ

# 54. canonical
原則自己参照canonical。

パラメータ違い等の重複URLがある場合は代表URLへ集約する。

# 55. robots.txt
Googlebot等による重要コンテンツのクロールを妨げない。

AI OverviewsやAI ModeについてGoogleは通常のGoogle Searchと同じ基盤を利用しており、AI専用の追加マークアップ等は不要としている。

# 56. 画像SEO
人手不足研究所では画像・グラフも情報資産として扱う。

特に、

- 独自グラフ
- 統計比較
- インタビュー写真
- 図解

を重視する。

# 57. alt
画像内容を説明する自然なaltを設定する。

SEOキーワードの詰め込みは行わない。

# 58. グラフ
可能な限り、

タイトル

グラフ

要点

出典

をセットにする。

画像だけでなく、重要数値・結論はテキストでも記述する。

GoogleもAI検索向けに、重要コンテンツをテキストとして利用可能にすることを推奨している。

# 59. インタビュー画像
企業・人物写真には適切なalt・captionを付与する。

写真提供元やクレジットが必要な場合は03のAsset情報等を利用する。

# 60. 動画
将来的にYouTube等と連携する場合、Article / Interviewページ内への動画埋め込みも検討する。

動画だけに情報を閉じ込めず、重要な内容はテキストとしても掲載する。

# 61. 更新戦略
人手不足・採用市場・統計等は変化する。

Article・Reportを公開後放置せず、必要に応じて更新する。

# 62. 更新対象
優先度が高いもの：

- 統計データ
- 採用単価
- 求人市場
- 法制度
- システム・IT情報
- 市場動向

# 63. Evergreen記事
恒久記事ではURLを維持しながら内容を更新する。

/recruiting/construction-labor-shortage/

のようなページは定期更新候補。

# 64. 年次Report
年ごとの調査結果そのものに価値がある場合は、

/reports/construction-labor-shortage-2026/

/reports/construction-labor-shortage-2027/

のように年度別に保持する。

# 65. 更新履歴
重要な更新は03のrevisionsを利用して表示可能とする。

# 66. カニバリ防止
新規記事作成前に、必ず既存ページを確認する。

以下を確認：

- 同じ検索意図の記事がないか
- 既存記事への追記で対応できないか
- Reportとの役割が重複しないか
- テーマハブで対応すべき内容ではないか

# 67. 1検索意図1代表ページ

を別記事にしない。

# 68. SEOランディングページ追加基準

- 検索需要がある
- 複数の関連コンテンツがある
- 独自情報を掲載できる
- 既存ページと検索意図が重複しない
- 継続更新できる
