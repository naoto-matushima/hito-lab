**文書名:** 15-reference-sites.md

# 1. 直接競合

## 現場改善ラボ（Tebiki株式会社）
https://tebiki.jp/genba/

製造・建設・物流・小売・サービスの現場産業向け。SaaSベンダーのオウンドメディアで会員十数万規模。

**見るところ**

- 業界×テーマの二軸ナビゲーション
- 識者インタビューのカード設計（話者を前面に出す型）
- セミナー・ウェビナーへのCV導線

**真似しないところ**

- ウェビナー登録への導線の強さ（07 §64に反する）
- カードが多数並ぶ前提のグリッド密度（06 §101-2）

## 現場ラボ
https://genba-lab.com/

現場監督経験者による建設特化。教育動画・研修・ツール販売が中心。

**見るところ**

- 運営者の顔が見えるトーン。一人運用の人手不足研究所と親和性が高い

**真似しないところ**

- サービス販売の比重。メディアとサービスの境界が曖昧

## 施工の神様
https://sekokan-navi.jp/magazine/

建設現場のリアルを現場目線で伝えるメディア。失敗と技術の2視点。

**見るところ**

- インタビュー記事のレイアウト
- 成功事例に限定しない編集方針（10 §23と同じ発想）

## 建設ITラボ（アイピア）
https://aippearnet.com/

建設DX・業務効率化。BIM/CIM、ドローン、クラウド型施工管理システムなど。

**見るところ**

- テーマカテゴリの粒度
- システム比較記事の構成（将来のIT系Articleの参考）

# 3. サイト構造・ナビゲーション

## WORK MILL（オカムラ）
https://workmill.jp/jp/

**最重要の参考例。** 05の改訂（v1.1）の多くはここから来ている。

**見るところ**

- `/concept/{slug}/` — ブランド視点（キャリア・学び・共創）を独立ページ群として持つ構造。01 §4「ブランド言語とSEO分類の分離」がUI上でどう現れるかの実例 → 05 §16-2
- サイドバーの「記事を探す」— タグクラウドではなく、concept別に編集されたキーワードを3〜4個だけ出す。ラベルが「「ぜんぶ」を出し合うチームをつくる」のように編集された日本語 → 05 §81
- 記事のイラスト運用。写真がない記事のEyecatch解 → 06 §101-3
- メルマガ登録CTAの繰り返し配置 → 05 §65-2
- About: https://workmill.jp/jp/about/ — ステートメント → 活動 → メンバー → 刊行物 → 歴史年表。信頼の作り方
- MEMBER: https://workmill.jp/jp/about/member/ — 運営メンバーの見せ方
- パンくずをページ最下部に置いている

**真似しないところ**

- ナビゲーション8項目は多い。初期は5〜6に絞る
- イベント枠。Phase 1では持たない

## Biz/Zine（翔泳社）
https://bizzine.jp/

**見るところ**

- テーマURLがフラットな単語1つ（`/bizdev/` `/strategy/` `/organization/` `/dx/`）。人手不足研究所の `/recruiting/` `/organization/` `/dx/` `/management/` と同じ設計で、02の裏付けになる
- 「テーマから探す」と「記事スタイルから探す」を並列に置くナビ設計
- 連載を第一級オブジェクトとして持つ（`/article/corner/{id}/`）→ 05 §81-2
- 特集ページ（`/keieikanri/` 等）に記事を順次格納する運用 → 02 §6のテーマハブ運用
- 執筆者一覧（`/person/`）
- 記事タイトルの型：企業名＋具体的な問い。キーワード詰め込みをしない → 04 §19
- ニュース（短報）と記事（取材もの）の分離

**真似しないところ**

- 特集ページのURL命名が不統一（`/keieikanri/` と `/Special01_BD/` が混在）。02 §38の命名ルールを守る理由がここに見える
- アクセスランキング（今日/週間/月間）。記事数が少ない段階では逆効果
- 会員登録ゲート。初期は全記事を開放する

## ジチタイワークス
https://jichitai.works/

自治体職員向け。読者の性質が近い（硬い立場、実務、予算制約）。

**見るところ**

- 硬い読者層に対する親しみやすさの出し方 → 06 §1
- 紙媒体からの抜粋をWebに載せる二毛作の構造。将来Reportを冊子化する場合の参考

**真似しないところ**

- トップのタグ一覧の密度が高い。06 §101-2の方針に反する

## 日本の人事部
https://jinjibu.jp/

**反面教師として見る。**

**見るところ**

- 企業をデータベースとして持つ構造 → 07 §48の企業DB構想の完成形

**真似しないところ**

- 情報密度。06 §101で避けると決めた「官公庁化」に近い

# 5. 論点別の見比べ表

数を見るより、同じ論点で2〜3サイトを比較する方が判断が早い。

| 決めたい論点 | 見比べる組み合わせ | 関連設計書 |
| --- | --- | --- |
| ナビをテーマ軸にするか形式軸にするか | WORK MILL（形式） vs Biz/Zine（両方） vs 現場改善ラボ（業界×テーマ） | 02 §33 |
| テーマハブの育て方 | Biz/Zine（特集） vs パーソル総研（特設サイト） | 02 §6 / 05 §18 |
| ブランド思想の置き場所 | WORK MILL（/concept/） vs 他社（Aboutのみ） | 05 §16-2 |
| Report詳細の情報量 | パーソル総研 vs works-i | 05 §41 |
| 硬さと親しみやすさの配分 | ジチタイワークス vs works-i vs 日本の人事部 | 06 §1 |
| 写真がないときのEyecatch | WORK MILL（イラスト） vs パーソル総研（タイポ・図版） | 06 §101-3 |
| タグ探索UI | WORK MILL（キュレーション） vs ジチタイワークス（全件） | 05 §81 |
| 初期の情報密度 | どのサイトも密度が高い。反面教師として | 06 §101-2 |
