# 人手不足研究所｜サイト立ち上げ基本設計書 v0.1
## 1. プロジェクト概要
### サイト名
**人手不足研究所**

### 位置づけ

独自ドメインで運営する独立メディアとする。既存メディア（新規事業開発ノート）のサブカテゴリや姉妹メディアという扱いにしない。

新規事業開発ノートに公開済みの採用・人手不足系記事は、人手不足研究所へ移設する。移設後、新規事業開発ノートは新規事業・創業をテーマとするメディアとして継続し、人事・採用テーマは扱わない。

競合環境・差別化・チャネル・運用体制は12 メディア戦略で定義する。

### サイトの目的
建設・介護・物流・製造・宿泊など、人手不足の影響を強く受ける企業に対して、採用・組織・人事・業務改善・DX・IT活用に関する情報を提供する調査・実践メディアを構築する。

単なる情報発信メディアではなく、独自調査、企業インタビュー、業界レポートなどを通じて企業との接点をつくり、将来的には採用支援、Web制作、業務改善、Excel・ファイル整理、ITアドミン支援、システム開発などの相談・案件につなげる。

# 2. ブランド戦略
## 2-1. ブランドビジョン
**人が減っても、強くなる会社へ。**

人口減少や人手不足が進むなかでも、必要な仕事や事業を持続させ、さらに成長できる会社を増やす。

## 2-2. ブランドの基本思想
人手不足に対して、企業が取り得る方法を広く扱う。

### 採る
必要な人材に選ばれる会社をつくる。

### 活かす
人が力を発揮し、長く働ける組織をつくる。

### 減らす
業務を見直し、ITや仕組みによって仕事の負担を減らす。

### 強くする
生まれた余力を、人・顧客・事業へ再投資し、企業としての魅力や競争力を高める。

この4つを独立した施策としてではなく、循環する経営活動として捉える。

## 2-3. メディア説明
人手不足研究所は、建設・介護・物流・製造・宿泊など、人手不足に向き合う企業のための調査・実践メディア。

採用、組織・人事、業務改善、DX・IT活用など、「人」と「仕事」の両面からこれからの会社づくりを考える。

統計データの分析だけでなく、企業、働く人、採用・人事・ITなどの支援会社へのインタビューや独自調査を通じて、実際の企業経営に役立つ情報を提供する。

# 4. 主要な顧客課題
サイトでは以下のような課題を扱う。

### 人材確保
- 求人を出しても応募がない
- 採用単価が上がっている
- 若手が採れない
- 採用媒体の選び方が分からない
- 自社の魅力を伝えられていない

### 組織・人事
- 採用しても定着しない
- 教育が属人的
- 評価制度がない
- 管理職の負担が大きい
- 若手育成がうまくいかない

### 業務負担
- Excelが複雑化している
- ファイルが散在している
- 二重入力・転記が多い
- 紙業務が残っている
- 担当者しか分からない業務がある

### IT・DX
- どのシステムを使えばいいか分からない
- SaaSを導入しても定着しない
- システム開発すべきか判断できない
- AIをどう活用すればいいか分からない
- 社内にIT担当者がいない

### 事業・顧客接点
- Webサイトが古い
- 問い合わせが少ない
- 顧客体験が悪い
- 宿泊施設等で直接予約を増やしたい
- ITを使って売上や利益を改善したい

# 11. 技術方針

- Vercel

初期段階ではCMSを導入せず、Claude Codeを開発・運用の実行環境として記事・サイトを更新する。

Claude Codeを前提とするため、以下をリポジトリに同梱する。

- CLAUDE.md（プロジェクト共通の前提・禁止事項・検証コマンド）
- .claude/rules/（設計領域ごとのルール。パス限定で読み込ませる）
- .claude/skills/（記事追加・Report追加・Interview追加などの反復手順）
- .claude/settings.json（権限設定。本番DB・Secretへの到達を機構的に禁止）

これらは「人間が毎回説明し直さなくても、同じ設計判断が再現される」ための資産として扱う。

コンテンツ量・編集人数が増えた場合はHeadless CMSの導入を検討する。

# 17. Claude Code実装時の基本原則
Claude Codeにサイト全体を一度に実装させない。フェーズ単位で作業範囲と完了条件を渡す。

実装では以下を重視する。

- 再利用可能なコンポーネント
- コンテンツとデザインの分離
- 記事追加時にコード修正を極力不要にする
- 業界・地域・テーマを後から追加可能にする
- SEO情報を記事単位で設定可能にする
- CMSを後から導入可能な構造にする
- UIより先に情報構造を固定する
- 初期段階で過度な機能開発を行わない

Claude Codeを使う上での運用原則は以下とする。詳細は09で定義する。

- 設計変更が必要と判断した場合、コードを変更する前に理由と変更案を報告させる
- 大きな変更に着手する前にプランモードで計画を出させ、人間が承認してから実装させる
- 検証手段（typecheck / lint / content validation / build）を必ず与え、通ったことを確認させる
- 本番DB・Production Secret・公開設定は権限設定で到達不能にし、指示文だけに依存しない
